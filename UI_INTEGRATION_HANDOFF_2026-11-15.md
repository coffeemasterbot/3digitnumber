# UI integration handoff — 15 November

This describes the shared source as inspected. Final build and integrated verification belong to Astra.

- Homepage uses `assets/game-covers/${g.art}.jpg`, labelled 遊戲插畫. `build.cjs` copies `source/game-covers`. Offline conversion embeds the images.
- `createGameAudio(sources, stopLegacyMusic)` creates one player per game document. The build currently injects `window.gameAudio` into non-home pages, with manifest IDs resolved to local paths. `track(id)`, `effect(id, eventId)`, `volume('music'|'effects', 0..1)`, `pause()`, `resume()`, and `dispose()` are available. `eventId` is optional but must be unique per authoritative event and stable across duplicate delivery. Use distinct IDs for separate kills in one blast and a fresh instance per game document. Existing calls in game-shell and FPS omit IDs, so deduplication is not yet wired. Current event cache is capped at 512 entries.
- The player pauses on document hidden and disposes on pagehide. Each game must explicitly resume only after its own pause/visibility state permits it. Wire visible music and SFX controls to both `volume` channels. In particular FPS `saveSettings()` currently changes only its synthesized master gain, and its mute gates new effect calls without silencing an already-playing MP3. Garden/runner shell pauses the shared player on mute. Jet's existing sound toggle must synchronize with both music and effects. Preserve and restore previous slider levels when toggling mute.
- Avoid simultaneous legacy music. Garden/runner game-shell skips its synthesized music when `window.gameAudio` exists. Jet `useSound.ts` takes the shared player branch for BGM. Forest must route its existing `moneyJourneyMusic` lifecycle to forest track without continuing synthesis. FPS still has its own synthesized music; no FPS music track is specified, while kill/reload use shared effects. Check these transitions in normal and offline builds.
- `detailed-games/weapon-finish.mjs` exports `addWeaponFinish(group,type)`. Call once after constructing the weapon group in each rebuild, passing the actual weapon key including `bazooka`. The owning viewmodel disposal must dispose the added geometry/materials. Current `fps-entry.js` has no import/call, and coop requires its own matching integration.
- Jet renderer consumes `player.dashFrames`, `player.vehicleVisualState = {gravity:'up'|'down', airborne, active, velocityY}`, and `player.teleportPreview = {targets:[{id,y,safe}],nextId}`. The engine computes the preview and actual destination. HUD hides the timer for six vehicles; timed effects retain their timer. Review visual state on pause and reduced motion.
- Runner Player consumes `extras.airKind` (null, jetpack, pogo), `flightPhase` (idle, takeoff, cruise, warning, landing), `pogoPhase` (idle, rise, fall), and the authoritative `airHeight`. Direct and magnetic coin collection must emit the same unique event identity once.
- Forest renderer reads `map.light.source`, `receiver`, `mirrors[].turned`, `segments`, and `lit`; keep rendering tied to traceLight results.
- The standalone audio fixture previously covered gesture, crossfade mute, effect deduplication, pause/resume, and disposal. The six-vehicle rendering fixture was source-only. Verify integrated desktop/touch, volume, exit and offline behavior after final build. No new build or tests were run for this handoff.
